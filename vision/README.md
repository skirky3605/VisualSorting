# 智能分拣视觉工具（vision）

目标：从相机画面中识别物料的**颜色 + 形状**，并输出机械臂抓取所需的**姿态**
（工作台坐标 mm + 偏航角 °）。ESP32-S3 只负责出图（MJPEG 流），识别与姿态解算放 PC 端。

> 本目录是代码目录；测试图片、评估输出、总说明在上一级项目根目录。

---

## 1. 方案评估：为什么用「颜色分割 + 几何判别」

| 方案 | 数据需求 | 本机可跑 | 姿态输出 | 评价 |
|---|---|---|---|---|
| **A. 传统视觉：Lab 颜色分割 + 轮廓几何判别**（本方案） | 无需训练数据 | 是，CPU 单帧 ~10ms | 直接来自轮廓（中心/长轴/缺口朝向） | 场景是**固定工位 + 高饱和纯色 + 少量已知形状**，颜色与背景色度差极大（物体 chroma 30~55，纸板 <12），几何判别完全够用；可解释、易调参 |
| B. 深度学习检测（YOLO-OBB / 分割，自训） | 需数百张标注 + 训练 | 本机无 GPU、无 ultralytics | OBB 角度仍是图像平面角，照样要标定 | 泛化最好，但对 7 件固定物料是杀鸡用牛刀；后续若要支持新物料再上 |
| C. 端侧 ESP-DL 推理 | 需量化模型 | ESP32-S3 仅几 FPS | 精度受限 | 适合做「有无物料」触发，不适合姿态解算 |
| **A + 小 CNN 二次确认（推荐演进路线）** | 少量裁剪样本 | 是（py310 有 torch / onnxruntime） | 同 A | 形状判别出现歧义时（见第 5 节三棱柱问题），对**裁剪图**训一个小分类器，成本远低于整图检测 |

结论：**现在用 A，把标定与姿态链路打通；B 作为后续升级路径。**

---

## 2. 文件说明

| 文件 | 作用 |
|---|---|
| `sorter_vision.py` | 主程序：颜色分割 → 连通域 → 形状判别 → 姿态；支持单图 / 批量 / ESP32 MJPEG 实时流 |
| `calibrate.py` | 单应标定：4 个角点像素 + 实际尺寸 → `calib.json`（像素 ↔ 工作台 mm），带网格自检图 |
| `evaluate_views.py` | 候选机位定量比较（内置 4 张样张真值），输出检出率/分类正确率/误检/透视失真 |
| `feature_probe.py` | 打印每个连通域的全部几何特征，用于重标形状阈值 |
| `palette_probe.py` | K-means 统计主色 + 指定像素采样，换灯光后重标颜色阈值 |

## 3. 使用方法

环境：conda 环境 `py310`（cv2 5.0 / numpy / scipy / torch-cpu）。
**建议在项目根目录（上一级）用相对路径运行**：PowerShell 把中文路径当参数传给
python.exe 时会乱码，用相对路径（纯 ASCII）最稳。

```powershell
$py = "C:\Users\skirky\miniconda3\envs\py310\python.exe"

# 单张图片，输出标注图 + JSON
& $py vision\sorter_vision.py test1.jpg --out out\test1_annotated.jpg --json out\test1.json

# 固定相机后先标定（4 个角点像素 + 标定板实际尺寸）
& $py vision\calibrate.py --points "300,700;1180,690;1210,120;320,110" `
      --size-mm "520,430" --out calib.json --check test1.jpg --check-out out\grid.png

# 带标定 + 工作区 ROI（ROI 外的背景杂物直接丢弃）
& $py vision\sorter_vision.py test1.jpg --calib calib.json --roi-poly "300,300;900,250;1050,800;350,800"

# 接 ESP32-S3 视频流实时识别（跑 300 帧并存一张标注快照）
& $py vision\sorter_vision.py --url http://192.168.4.1:81/stream --frames 300 --snapshot out\snap.jpg

# 四个候选机位定量比较
& $py vision\evaluate_views.py test1.jpg test2.jpg test3.jpg test4.jpg `
      --out-dir out --csv out\views.csv --json out\views.json
```

## 4. 算法细节

**颜色（Lab 色相角）**：`hue = atan2(b-128, a-128)`，实测分布

| 类别 | 色相角 | chroma |
|---|---|---|
| 品红/粉 | -115° ~ -8° | 30~50 |
| 黄 | 96° ~ 124° | 38~53 |
| 绿 | 124° ~ 200° | 26~55 |
| 纸板/桌面背景 | 任意 | **< 12** |

先用 `chroma >= 26` 确认物体，再用 `chroma >= 13` 的宽松阈值**迟滞回收**被阴影压暗的
侧面与高光冲白的顶面，但一个宽松连通域内必须有 ≥12% 的严格像素才被接受
（避免把纸板阴影误判为黄色物体）。

**形状判据**（规则表 `SHAPE_RULES`，从上往下匹配、命中即返回，阈值由 4 张样张标定；
新增形状的做法见第 6 节）：

1. `solidity = 轮廓面积/凸包面积 <= 0.80` → **拱桥**（U 形缺口；斜视时缺口被压扁，
   再由 `defect_ratio >= 0.45` 辅助）
2. `hull_circ >= 0.90` 且（`max_turn <= 62°` 或 `hull_verts_fine >= 9`）→ **圆柱**
   （圆/椭圆边界平滑无尖角；立方体的直角棱边最大转角 > 68°）
3. `hull_aspect >= 1.5` → **长条**
4. `hull_extent <= 0.78` → **三棱柱**（斜视露出三角端面，凸包填充率明显偏低）
5. 其余 → **立方体**

**姿态**：

* 位置 = 轮廓外接旋转矩形中心；角度 = 长轴方向（图像坐标系，右为 0°、逆时针为正）
* 拱桥额外输出 `notch_dir_deg`（凸包最深缺陷方向 = 缺口朝向）
* 标定后把方向向量过单应矩阵映射到工作台坐标系，得到 `yaw_deg` 与 `table_xy_mm`
* 对称性提醒：圆柱 yaw 无意义；立方体 90° 等价；长条/棱柱 180° 等价；
  拱桥必须用 `notch_dir_deg` 才能唯一确定抓取姿态

## 5. 四个候选机位评估结果

真值：每张图 7 件物料（粉色长条、绿色长条、小立方体、立方体、绿色三棱柱、
黄色拱桥、黄色圆柱）。ROI = 真值凸包外扩 130px，近似「工作区」。

| 指标 | test2（低角度大视野） | test4（低角度近拍） | test3（中俯视≈40°） | **test1（近正俯视）** |
|---|---|---|---|---|
| 检出（工作区内/真值） | 6/7（两件粘连成一体） | 7/7 | 7/7 | **7/7** |
| 工作区内误检 | 0 | 0 | 0 | **0** |
| 工作区外误检（背景杂物） | 4 | 1 | 1 | **0** |
| 颜色+形状分类正确 | 5/7 | 4/7 | **7/7** | 6/7 |
| 中位 / 最小物体面积(px) | 17204 / 7532 | 11489 / 6634 | 7447 / 5517 | 10153 / 5794 |
| 物体间最小间距(px) | 1.4（相邻） | 4.0 | **0.0（相连）** | 2.8 |
| box 类填充率 hExt 中位（顶面可见度） | 0.845 | 0.882 | 0.895 | **0.956** |
| 透视收敛比（对边长度比，1.0=正交） | 1.374 | 1.503 | 1.155 | **1.143** |

失败模式：

* **test2**：立方体与三棱柱在图像中粘连成一个连通域 → 漏检 1 件并误判；背景有 4 个
  同色杂物造成误检（可用 ROI 消除，但视野被浪费）。
* **test4**：绿色长条长轴几乎沿视线方向，长短轴比从真值 1.71 被压缩到 1.05（-39%），
  形状与姿态都不可信；三棱柱被压成近似方形。
* **test3**：7/7 全部识别正确，但物体最小间距 0px（物料靠近就会粘连）、
  分辨率余量最低，hExt 仅 0.895（斜视压缩明显，姿态精度低于 test1）。
* **test1**：工作区内零误检、几何最接近正交投影（hExt 0.956、透视收敛 1.143）、
  分辨率充足；唯一失败是把三棱柱判成立方体——**近正俯视时三棱柱的俯视足迹就是矩形**，
  脊线只体现在明暗上。

### 结论

**推荐 test1（近正俯视）作为分拣工位的主相机位**：几何失真最小
（透视收敛 1.14 → 位置/角度最可信）、工作区内零误检、物体像素数充足；
三棱柱的歧义用下面任一方式解决（推荐第 1 条）：

1. 相机**保留 10°~25° 小倾角**（不要绝对垂直），让三棱柱的脊线与两个斜面露出明暗
   分界，hExt 仍可保持 >0.93，姿态精度几乎不受影响；
2. 正上方 + 单侧补光，用代码里现成的 `brightness_split()`（Otsu 明暗双峰占比）做二次
   确认：双峰各占 30% 以上判为三棱柱，并可顺便给出脊线方向＝抓取朝向；
3. 若允许两套方案，test3 作为「识别优先」的备选，但必须解决物料粘连
   （分水岭分割或给摆放位置加间距约束）。

不推荐 test2 / test4：低角度造成的尺寸压缩（-39%）会直接变成机械臂的定位与转角误差，
且视野里全是需要额外处理掉的背景杂物。

## 6. 如何添加新形状 / 新颜色

形状判别已做成**数据驱动的规则表** `SHAPE_RULES`（在 `sorter_vision.py` 顶部），
新增形状 = 加一行，不用改判别逻辑。

1. **拍样张**：新形状单放或与现有物料混放，拍 3 张以上（不同位置 + 目标机位），
   存到项目根目录，例如 `newshape_1.jpg`。
2. **看特征**：`& $py vision\feature_probe.py newshape_1.jpg --min-area 1500`
   每行末尾会显示「当前命中了哪条规则」，同时给出全部候选判别量：
   `hExt` 凸包填充率 / `hAsp` 长短轴比 / `hCirc` 凸包圆度 / `turn` 边界最大转角 /
   `d/min` 缺口深度比 / `splMin` 明暗双峰占比 / `A/hull` 轮廓与凸包面积比。
3. **找分界**：把新形状这些量的取值范围，和现有 5 类（以及 test1~4 上的实际分布）
   对比，找一条**不重叠**的分界；同时留出余量（别贴着现有物料的边界取阈值）。
4. **加规则**：在 `SHAPE_RULES` 里、**兜底那条 `("cube", [])` 之前**插入。
   例如新增「圆锥」，实测 `hExt≈0.62`、`hCirc≈0.90`，而三棱柱是 0.69~0.78：

   ```python
   ("cone", [("hull_extent", "<=", 0.65), ("hull_circ", ">=", 0.85)]),
   ```

   一条规则里的多个条件是「与」；同一形状写多条规则 = 「或」
   （斜视/俯视需要不同判据时就靠这个，参考 `arch` 和 `cylinder` 的写法）。
5. **回归验证**：在 `evaluate_views.py` 的 `VIEWS[...]["gt"]` 里按
   `(颜色, 形状, 中心像素)` 补上新形状的真值，跑一遍评估，确认
   **分类正确率没有下降、且原有物料没被新规则抢走**（看 `错误明细`）。
6. **收尾**：在 `SHAPE_CN` 里补中文名（用于文档/表格）。检测 JSON 会自动带上新特征，
   不需要改输出代码。

**如果现有特征分不开**，按代价从低到高：

| 手段 | 做法 | 适用情形 |
|---|---|---|
| 加一个几何特征 | 在 `measure()` 里算出来并加进返回字典即可（自动进入规则表与 JSON 输出） | 形状在轮廓上确有差别，只是现有量没测到（可加「平行边对数」「角点数」等） |
| 明暗/脊线判据 | 用现成的 `brightness_split()`（Otsu 明暗双峰占比），例如正俯视下三棱柱与立方体剪影相同、只有脊线明暗能分 | 俯视时剪影重合的立体形状 |
| 小 CNN 二次确认 | 对 `detect()` 输出的裁剪图训一个小分类器（py310 有 torch / onnxruntime），在 `detect()` 之后覆盖模糊样本 | 几何量严重重叠，或物料表面有图案 |

**新增颜色**同理：在 `LAB_HUE_RANGES` 加一行 `"blue": (色相下限, 上限)`，
再在 `ANNOT_BGR` 加标注颜色。色相角范围可以先拍一张，用
`palette_probe.py --min-chroma 22` 看主色落在哪一段。

## 7. 已知限制 / 下一步

1. **粘连**：同色物料在图像中相连时会合并成一个连通域。下一步加距离变换 + 分水岭，
   或按抓取位分格上料（每次只放一件）。
2. **三棱柱判据**：见第 5 节结论；`brightness_split` 双峰判据需要在更多样张上验证。
3. **标定**：`calibrate.py` 已实现，需在真实工位跑一次并核对网格自检图，
   之后 `yaw_deg` / `table_xy_mm` 才可直接下发给机械臂。
4. **光照**：色相阈值对色温敏感，换灯后用 `palette_probe.py` 重新出一遍主色表。
5. **与 ESP32 联动**：目前是「ESP32 出流 → PC 识别」；闭环还需把
   `table_xy_mm / yaw_deg` 发给机械臂控制器（串口或 TCP）。
